第 2 页 / 提效场景

老师手动整理一份课堂服务包要 50 分钟，识别逐字稿不到 5 分钟。

这不是说现在还得老师手动做。而是：如果老师自己来——逐个知识点提取、整理成学生能看的复习笔记、再逐条展示，一份单课服务包大概 50 分钟；现在系统识别课堂逐字稿自动生成，老师只做质检确认，不到 5 分钟，上传现成笔记更快。

第 5 页 / 权限管理

涉及学生和家长的数据，就要按角色把权限分清楚。

伴课已经是跑通、发布出来的妙搭 App，所以这一页不再讲“是不是真的”，而是讲权限——既然要给学生和家长用，普通学生的数据就必须按角色隔离。

管理员 / 老师能看整个数据库；老师只管理、查看自己的学生。
学生通过专属链接进入，只看到自己要复习的内容，看不到别人。
家长在系统里设一个独立身份，只看自己孩子的特定数据。
怎么接入学生 / 家长用手机号注册个人版即可使用；当前先用专属链接轻量隔离，后续按角色正式设计身份。

第 7 页 / 迭代过程

70+ 次伴课迭代：有妙搭反馈、老师肯定，也有真实踩坑和版本记录。

对接老师 · 卜征：开放资源、约沟通辅导、反馈「整体挺好，可以再微调」——外部反馈推着伴课往前改。
上课之余的投入：连续 36 天、最长单次 8 小时、累计 33 亿 token——一线老师也能把想法做出来。
伴课 version history 70+ 从 idea、plan、互相 review，到 bug 修复和页面收敛。

我先让妙搭出一版 plan，再把 idea 交给 Codex 和 Claude Code 互相 review，找风险点、拆任务、推进实现。这个过程不是一次生成，而是反复验证、修 bug、一路收敛出来的。

妙搭反馈机制

它会持续追问输入能力、内容来源和字段设计，推动方案更准确。

第 8 页 / 反馈和边界

组长、助教、顾问三类反馈，让伴课从“生成内容”收敛成“服务流程”。

组长反馈 认可与建议

组长老师肯定了这套课后服务系统——可作为课程附加服务、提升复习效率、也能引流，建议继续做下去。

助教反馈 轻量跟进

助教需要更清楚的检查项，但不能增加很重后台，所以先保留最关键的两个动作。

顾问反馈 家长收获感

顾问强调：家长花了钱，最想每节课都看到孩子的具体问题和加强点——要给家长实时的“收获感”。

真实试点阶段，先把主链路证据做扎实，再谈推广。
